## 五、构建脚本清单

`build/` 目录下的脚本按执行顺序如下：

| 脚本 | 作用 | 何时运行 |
| --- | --- | --- |
| `process_art.py` | 裁掉生成图底部水印，压缩为 WebP | 更换插画时 |
| `sync_assets.py` | 同步 `src/assets` 与 `03_资源文件/images_webp` | 更换插画后 |
| `remap_keys.py` | 知识点编号与关卡对应关系重映射 | 调整关卡结构时 |
| `merge_data.py` | 合并分片数据文件为单一数据源 | 调整关卡结构时 |
| `patch_basis.py` | 批量替换不可核查的规范依据 | 依据核查后 |
| `fix_basis2.py` | 修正依据中的标准编号与名称错误 | 依据核查后 |
| `fix_burn_eye.py` | 调整急救类知识点所属关卡 | 调整关卡结构时 |
| `audit_basis.js` | 依据可核查性审计，区分标准类与法规类 | 每次改数据后 |
| `verify.js` | 10 项数据与文件自检 | 每次改数据后 |
| `gen_basis_doc.js` | 由数据源生成依据清单 | 改数据后同步文档 |
| `gen_levels_json.js` | 由数据源生成关卡配置 | 改数据后同步配置 |
| `build_single.py` | 内联打包为自包含 HTML | 每次发布前 |
| `make_exe.py` | 生成 Windows 自解压 exe | 每次发布前 |
| `e2e.js` | 端到端自动通关测试 | 每次发布前 |
| `make_submission_zip.py` | 生成提交压缩包（完整版 / 精简版） | 提交前 |
| `check_zip_playable.js` | 验证解压后的单文件能否直接运行 | 提交前 |

数据修正类脚本（`remap_keys`、`merge_data`、`patch_basis`、`fix_basis2`、`fix_burn_eye`）为一次性操作，保留用于追溯改动过程，再次执行前需确认是否会与当前数据冲突。
