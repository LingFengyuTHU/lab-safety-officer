# 运行说明

本文件说明《实验室安全官》2.0 的运行方式、修改方法与目录结构。

---

## 一、运行方式

### 方式一：双击 HTML（推荐）

打开 `01_可执行文件/实验室安全官.html`，双击即可。

不需要安装，不需要联网，不读写任何本地文件。该文件为自包含单文件：样式、脚本、11 张插画全部以 Base64 形式内联其中，体积 846 KB。

浏览器兼容性：Chrome、Edge、Firefox、Safari 近两年版本均可正常运行。游戏同时支持鼠标拖拽与触屏点选，手机浏览器可直接游玩。

由于不加载任何外部资源，将该文件复制到U 盘、通过邮件附件发送、或放入任意 HTTP 服务下运行，效果完全一致。

### 方式二：双击 exe

打开 `01_可执行文件/实验室安全官.exe`，双击即可。

该文件是 Windows 自解压包，内部封装了同一个 HTML 与一个启动批处理。执行时先解压到系统临时目录，再调用系统默认浏览器打开游戏。首次启动比方式一慢一到两秒，属正常现象。

三点需要说明：

1. 它不是原生程序，不写注册表，不安装任何组件，关闭后临时目录由系统自行清理。
2. 部分安全软件会对自解压文件提示「未知发布者」。这是自解压包的常见误报，不影响功能。如需规避，直接使用方式一。
3. 若系统临时目录有写权限限制导致解压失败，请改用方式一。

### 方式三：部署为静态站点

`docs/` 目录可直接作为静态站点根目录。`docs/index.html` 与 `01_可执行文件/实验室安全官.html` 内容相同，`.nojekyll` 文件用于阻止 GitHub Pages 忽略下划线开头的目录。

本地验证：

```bash
python -m http.server 8000 --directory docs
```

浏览器访问 `http://localhost:8000`。

部署到 GitHub Pages 的步骤见 `GitHub部署指南.md`。

## 二、常见问题

**打开后页面空白**

先确认浏览器版本。游戏使用了 CSS 自定义属性与 Grid 布局，2020 年之前发布的浏览器可能出现布局异常。换用较新版本的 Chrome 或 Edge 即可解决。

**拖拽无响应**

游戏同时实现了点击模式：先点选左侧待归位项目，再点选右侧目标容器。触屏设备建议直接用点击模式。

**杀毒软件拦截 exe**

见上文方式二第2 点。自解压包常被误判，可加信任或改用 HTML 方式。

**想修改题目或知识点**

用文本编辑器打开 `02_源代码/src/data/knowledge.js`。这是运行时唯一数据源，结构如下：

| 常量 | 内容 | 修改要点 |
| --- | --- | --- |
| `KNOWLEDGE` | 65 条知识点 | 每条含 `title`、`level`、`fact`、`basis`、`correct`，部分含 `equation` |
| `LEVELS` | 6 个关卡 | 每关含 `slots`（容器）、`items`（项目）、`traps`（禁忌组合） |
| `SCENARIOS` | 6 道情境题 | 每题含 `scene`、`q`、`opts`、`ans`、`why`（逐项解析）、`k`（关联知识点） |
| `REACTIONS` | 6 组配伍实验 | 每组含 `a`、`b`、`outcome`、`expect`、`result`、`describe`、`why`、`k` |

`level` 字段取四个值之一，决定知识卡的标题颜色与类型标签：

| 取值 | 显示为 | 含义 |
| --- | --- | --- |
| `danger` | 违规·危险 | 可能导致事故 |
| `warn` | 常见错误 | 不规范操作 |
| `ok` | 正确做法 | 应遵守的做法 |
| `info` | 地区差异·不作判定依据 |各地规定不一致，不判对错 |

新增知识点时注意三点：`level` 与内容性质必须匹配；`basis` 至少给出一条含标准编号或法规全称的依据；涉及颜色的条目必须注明地区差异并设为 `info`，因为颜色不得作为判定依据。

**改完后如何验证**

```bash
# 数据与文件自检（10 项）
node build/verify.js

# 依据可核查性审计
node build/audit_basis.js

# 重新生成依据清单与关卡配置
node build/gen_basis_doc.js
node build/gen_levels_json.js

# 重新打包单文件
python build/build_single.py

# 重新生成 exe
python build/make_exe.py
```

`verify.js` 检查关卡引用完整性、情境题与配伍实验结构、知识点编号与关卡对应关系、颜色条目是否声明差异、文件结构完整性、JS 语法与元素 id 交叉引用。

## 五、技术实现要点

**零外部依赖**。全部使用原生三件套，不引入框架，便于评委直接阅读源码，也避免依赖版本问题。

**单文件内联**。`build_single.py` 将图片转为 Base64 Data URI 内联到 HTML，并将数据源与逻辑脚本一并内联。生成后脚本会检查产物中是否残留外部引用，若有则报错退出。

**数据与逻辑分离**。全部可编辑内容集中在 `data/knowledge.js`，`js/game.js` 不含任何硬编码的题目或知识点。改数据不需要改逻辑。

**文档与数据同源**。`05_说明文档/知识点与规范依据清单.md` 与 `04_配置文件/levels.json` 均由脚本从数据源导出，不存在人工誊抄导致的偏差。

**无障碍与容错**。按钮元素使用原生 `button`，支持键盘 Tab 切换与回车触发；拖拽失败时回退到点击模式；配色以色块加文字标注双重编码，不单靠颜色传递信息。
